# NEXUS: известные ограничения и направления доработки

Документ описывает текущие границы платформы, риски и рекомендуемые улучшения. Предназначен для внутреннего планирования, онбординга и постановки задач в issue-трекере.

**Версия документа: 1.2** по состоянию репозитория (синхронизировать с релизами при необходимости).

---

## 1. Игровой движок (`engine/`)

| Область | Ограничение | Рекомендуемые действия |
|---------|-------------|-------------------------|
| **Архитектура** | Ядро не является оконным приложением: нет ввода, GPU-рендера и ECS уровня Unity. Вся графика и ввод — в клиенте Flutter. | Сохранять чёткую границу FFI/JSON; документировать контракт сцен. |
| **Физика** | Сущность–сущность: broadphase на сетке; узкое разрешение по-прежнему простое (оси, без continuous collision). Очень плотные кучи в одной ячейке всё ещё дают много пар. | Профилирование; при необходимости — SAP/sweep или более точный контакт. |
| **Анимация** | `EntityAnimator` в ядре — прежде всего таймлайн времени; детальная привязка кадров атласа — на стороне клиента. | Расширить ядро или зафиксировать контракт кадров в `GAME_AUTHOR.md`. |
| **Тайлмапы в рантайме** | Логика коллизий тайлов в Rust поддерживается; **полная отрисовка уровня из атласа в режиме Play** на стороне клиента ограничена (см. `GAME_AUTHOR.md`). | Реализовать отрисовку тайл-слоёв из `tileset` в `GameWorldPainter` / эквивалент; синхронизировать UV с экспортом сцены. |
| **Мобильные платформы** | Сборка и встраивание нативной библиотеки для iOS/Android — отдельный пайплайн (подпись, Runner). | Чеклист CI/CD для мобильных таргетов; артефакты `.so` / framework. |
| **Сравнение с коммерческими движками** | Сейчас нет частиц, навмеша, продвинутого аудио-DSP, полного редактора поведения в GUI и ряда подсистем «как у крупных движков». | **Цель продукта** — полнофункциональный 2D-движок с удобным редактором и предсказуемым UX; закрывать пробелы по дорожной карте. В коммуникации: заявлять это как направление развития и отмечать, что ещё в работе / превью, без скрытия текущих ограничений. |

## 2. Клиентское приложение (`client/`)

| Область | Ограничение | Рекомендуемые действия |
|---------|-------------|-------------------------|
| **Незавершённые экраны** | Часть пунктов на главной и в настройках — заглушки (магазин, лента и т.п.), намеренно отключены до реализации. | Реализовать экраны или скрыть навигацию до готовности. |
| **Редактор ассетов в сетке** | В коде зафиксированы TODO: открытие редактора кода/спрайта/скрипта по действиям из общей сетки ассетов. | Завершить маршрутизацию из `asset_grid` в существующие редакторы. |
| **Камера в редакторе** | Состояние камеры из ядра (`Camera2D`, follow) должно явно учитываться виджетом превью; иначе расхождение «в Rust есть — в UI не видно». | Единая подписка на FFI/снимок сцены для превью и Play. |
| **Веб-сборка** | Браузерные запросы к API требуют корректного `CORS_ALLOWED_ORIGINS` на сервере. | Документировать обязательные origin для каждого окружения. |
| **Совместная работа** | Облако и WebSocket покрывают сцену и студию проекта не полностью идентично всем типам ассетов; возможны конфликты версий (HTTP 409), гонки при одновременном сохранении. | UX: явные диалоги, «перезагрузить сцену», защита от безмолвной перезаписи локальных правок; расширить синхронизацию типов ассетов по одному паттерну со скриптами/спрайтами. |

## 3. Сервер и облако (`server/`)

| Область | Ограничение | Рекомендуемые действия |
|---------|-------------|-------------------------|
| **Биллинг** | При отсутствии `STRIPE_SECRET_KEY` checkout и webhook работают в **демо-режиме** (`billing.rs`). | Подключить реальный Stripe Checkout и проверку подписи webhook перед продакшеном. |
| **Безопасность по умолчанию** | В Docker по умолчанию может быть включена саморегистрация администраторов Waypoint (`ADMIN_OPEN_REGISTRATION=1`). | На публичном хостинге: `0`, ручное создание первого админа; сильный `JWT_SECRET`. |
| **Нагрузка** | Метрики и ingest увеличивают запись в БД; WebSocket-комнаты держат состояние в памяти процесса. | Лимиты, мониторинг пула соединений PostgreSQL, горизонтальное масштабирование при необходимости вынести в отдельный дизайн. |
| **Юридические страницы** | Политика конфиденциальности, условия использования и контакты для конечных пользователей приложения могут отсутствовать или быть неполными. | Подготовить юридические тексты и экраны в клиенте согласно юрисдикции. |

## 4. Администрирование и Waypoint

| Область | Ограничение | Рекомендуемые действия |
|---------|-------------|-------------------------|
| **Назначение** | Админ-панель и модуль `waypoint` — операционные инструменты (пользователи, проекты, ingest метрик и логов, задания, экземпляры и т.д.), а не игровой редактор NEXUS. | Чётко разделять WaypointMetric и игровой контур (клиент NEXUS, редактор, Nexus Cloud). См. также [WAYPOINT_METRICS.md](WAYPOINT_METRICS.md). |
| **Ingest** | Приём телеметрии зависит от валидных API-ключей и конфигурации лимитов нагрузки. | Нагрузочное тестирование; политика ретенции данных в БД. |
| **Эксплуатация** | Продакшен-ловушки (CORS, cookie, миграции, RBAC) не исчерпываются этой таблицей. | Чеклист: [OPERATIONS.md](OPERATIONS.md). |

## 5. Интеграции и прочее

| Область | Ограничение | Рекомендуемые действия |
|---------|-------------|-------------------------|
| **VK-бот** | Отдельный сервис; требует собственной конфигурации и развёртывания. | Сверять версии API ВКонтакте и секреты с `DEPLOY.md`. |
| **DB Agent** | Доступ к БД пользователя через агент — ответственность стороны, разворачивающей агент; облако не подключается к БД клиента напрямую. | Документ `AGENT_PROTOCOL.md`; аудит безопасности ключей. |
| **Покрытие тестами** | Тесты есть для отдельных модулей; полного e2e по всем сценариям может не быть. | Расширить smoke-тесты API, миграций, критичных путей FFI и коллаборации. |

## 6. Дистрибуция и MVP

К практическому чеклисту выпуска минимально жизнеспособного продукта относится также:

- эталонный шаблон проекта и пошаговый гайд «открыть → изменить → сохранить → запустить»;
- описанный и проверенный канал дистрибуции (например, itch.io, APK, архив для Windows);
- процедуры резервного копирования БД и ротации секретов (см. `DEPLOY.md`).

Подробности по авторам игр и движку: [GAME_AUTHOR.md](GAME_AUTHOR.md).
