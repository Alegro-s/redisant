## ВВЕДЕНИЕ

Современная индустрия разработки видеоигр опирается на специализированные **игровые движки** — программные платформы, объединяющие рендеринг, физику, управление ресурсами, скриптовую логику и инструменты создания контента. Коммерческие решения (Unity, Unreal Engine) обеспечивают широкую функциональность, однако связаны с лицензированием, закрытыми рантаймами и зависимостью от экосистемы вендора. Для учебных проектов, прототипирования 2D/3D-игр и исследования архитектуры «тяжёлого» нативного ядра актуальна разработка **собственного движка** с контролируемым набором зависимостей и прозрачным контрактом данных.

**Актуальность** темы обусловлена потребностью в кроссплатформенной среде, где редактор сцены, игровой плеер и серверная инфраструктура (облако, маркетплейс ассетов) работают с **единым форматом проекта** (JSON сцены v3, плагины, экспорт под Windows/Web/Android). Проект **Lynx** (репозиторий `Lynx/`) реализует такую платформу: клиент на **Flutter**, игровое ядро **Lynx Core** на **Rust** (`lynx-core/`), переходный рантайм `engine/` (FFI, LynxScript), документированные волны развития M1–M14 и регрессионные скрипты.

**Объект исследования** — процесс создания и эксплуатации кроссплатформенных 2D/3D-игр в среде разработки с собственным нативным ядром.

**Предмет исследования** — программная платформа Lynx и ядро Lynx Core: архитектура подсистем, контракт сцены, механизмы рендеринга (forward 3D PBR-lite), физики 3D, отсечения видимости и интеграции с Flutter-плеером.

**Цель работы** — разработать и описать игровую платформу Lynx на базе Lynx Core, обеспечивающую редактирование сцен, воспроизведение (Play), экспорт проектов и верифицируемое качество подсистем через автоматизированную регрессию.

**Задачи:**

1. проанализировать предметную область игровых движков и сформулировать требования к Lynx;
2. рассмотреть аналоги (Unity, Godot, Bevy и др.) и обосновать выбор Rust + Flutter;
3. спроектировать многоуровневую архитектуру (Hub, Client, Lynx Core, Legacy engine, Cloud API);
4. описать реализацию ключевых модулей Lynx Core: PAL/D3D12, forward 3D, плагин `lynx.3d`, физика 3D, frustum/Hi-Z culling;
5. разработать методику тестирования и представить результаты прогона регрессии;
6. оценить практическую применимость и направления развития.

**Практическая значимость** — готовая open-source база для курсовых и дипломных проектов по игровым технологиям, демо-проекты (`platformer-demo`, `platformer-demo-3d-room`), скрипты `run-*-regression.ps1`, документация для авторов игр (`GAME_AUTHOR.md`).

**Методы:** анализ литературы и документации, сравнительный анализ, проектирование ПО, прототипирование, модульное и интеграционное тестирование.

**Структура работы:** глава 1 — теория; глава 2 — проектирование и реализация; глава 3 — тестирование; заключение; приложения.

## 1 ТЕОРЕТИЧЕСКАЯ ЧАСТЬ

### 1.1 Предметная область и постановка задачи

**Игровой движок** — программный комплекс, предоставляющий разработчику абстракции над графикой, звуком, вводом, физикой, ресурсами и игровой логикой. В отличие от «голой» библиотеки (OpenGL, Vulkan), движок задаёт **жизненный цикл кадра**, формат сцены, систему компонентов или сущностей и pipeline рендеринга.

Платформа **Lynx** позиционируется как среда для **2D-платформеров** и **3D-сцен ограниченной сложности** (комната, PBR-объекты, terrain, скелетная анимация) с перспективой универсального ядра по модели id Tech / Source: минимум внешних зависимостей в hot path, собственные модули `math`, `render`, `physics`, `script`, `asset` (см. `docs/LYNX_CORE_ARCHITECTURE.md`).

**Функциональные требования к Lynx (выполненные и целевые):**

– редактирование сцены в Flutter-клиенте (объекты, слои, тайлмапы, плагины);  
– воспроизведение сцены (Play) с симуляцией 2D и overlay 3D;  
– нативный рендер 3D на Windows через D3D12 (`windows3dRuntime: core_forward_d3d12`, Q3);  
– контракт `extensions.lynx.3d` (камера, room, объекты, материалы, terrain, physics, culling);  
– LynxScript (байткод, VM в Rust) с опциональным legacy Lua в `engine/`;  
– экспорт проекта под платформы (Windows/Web/Android);  
– регрессионная проверка волн M1–M14 скриптами PowerShell.

**Нефункциональные требования:**

– детерминизм физики 3D на фиксированном шаге (≈1/60 с);  
– отсутствие Rapier/Bullet/wgpu в рантайме Lynx Core (собственный solver и D3D12 PAL);  
– версионирование API ядра (`CORE_API_VERSION`, `minLynxCoreVersion` в проекте);  
– документированные ограничения (`KNOWN_LIMITATIONS.md`).

**Проблематика**, мотивирующая Lynx Core:

– зависимость от тяжёлых коммерческих движков усложняет учебный и исследовательский доступ;  
– «универсальные» Rust-фреймворки (Bevy) меняют API быстрее, чем учебный проект успевает стабилизироваться;  
– разрыв между редактором (Dart) и нативным рендером требует чёткого **FFI** и JSON-контракта;  
– для 3D на мобильных и Web нужны разные PAL (Windows D3D12 реализован; WASM — stub, M6).

**Постановка задачи дипломного проекта:** спроектировать и реализовать ядро **Lynx Core** (`lynx-core`, версия `0.6.0-m6`) и интегрировать его в платформу Lynx (Client + engine FFI + демо-проекты), обеспечив сквозной сценарий: **сцена 3D-комнаты → Play → физика ящика → отсечение невидимых объектов → регрессионные тесты**.

### 1.2 Обзор технологий и аналогов игровых движков

**Классификация аналогов**

| Решение | Тип | Язык / стек | Сильные стороны | Ограничения для сравнения с Lynx |
|---------|-----|-------------|-----------------|----------------------------------|
| Unity | Коммерческий движок | C#, C++ runtime | Экосистема, Asset Store | Лицензия, закрытый runtime |
| Unreal Engine | Коммерческий движок | C++, Blueprint | AAA-графика | Высокий порог, размер |
| Godot | Open-source | C++, GDScript | 2D/3D, редактор | Другая архитектура сцены |
| Bevy | ECS-фреймворк | Rust | Data-driven, модульность | Не продукт «редактор+облако» |
| libGDX / MonoGame | Фреймворки | Java / C# | 2D/3D | Нет единого Lynx-редактора |
| **Lynx** | Платформа + Core | Rust + Dart | Свой Core, JSON v3, регрессия | 3D и WASM — в развитии |

**Теоретические основы рендеринга 3D (используемые в Lynx Core)**

– **Forward rendering** с одним направленным источником и картой теней 2048×2048 (M3, M12c: PCF 3×3, два каскада);  
– **PBR-lite:** albedo (текстура + CPU tint), metallic/roughness (скаляры);  
– **Скелетная анимация:** CPU skinning, clips GLTF (M13a);  
– **Terrain:** heightmap → mesh, LOD по дистанции (M13b);  
– **Отсечение:** frustum culling + CPU Hi-Z по буферу дистанций до камеры, occluder — задняя стена `room` (M14b).

**Теоретические основы физики 3D (M14a)**

– AABB-коллайдеры, статические плоскости комнаты, импульсное разрешение dynamic–dynamic;  
– без стороннего solver (Rapier) — предсказуемость и контроль hot path.

**Скриптовая подсистема**

– **LynxScript:** компиляция в байткод, VM (`lynx-core/src/script/`);  
– переходный **Lua** в `engine/` (feature `legacy_lua`).

**Вывод по теории:** Lynx занимает нишу **учебно-исследовательской платформы с собственным Rust-ядром** и Flutter-редактором; по возможностям 3D приближается к «лёгкому» forward-движку, уступая AAA-движкам по материалам, освещению и инструментам анимации.

### 2.2 Проектирование подсистем рендеринга, сцены и физики

**Проектирование конвейера кадра Forward3D**

1. Загрузка `Lynx3dScene` из JSON (`parse_extension`).  
2. Расчёт камеры orbit: `eye`, `view`, `proj`, `view_proj`.  
3. **Cull:** `Frustum::from_view_proj` — отсечение terrain/room/objects; **Hi-Z** — растеризация occluder (стены room), проверка дистанции до камеры (`cull3d.rs`).  
4. Сбор `Forward3DDraw` (mesh cache, albedo GPU M12b).  
5. Тени: два каскада `light_view_proj` / `light_view_proj_c1`.  
6. Передача кадра в PAL (D3D12) или Canvas preview (Dart).

*Рисунок 2 — Диаграмма последовательности «Сцена → Forward3DFrame → Present»* (вставить в Word)

**Проектирование физики 3D (M14a)**

– `Physics3dWorld::from_lynx3d_scene` создаёт тела из `objects[]` и плоскости из `room`;  
– шаг `step(dt)` с clamp `dt ≤ 1/15`;  
– FFI: `physics3d_world_create/load_lynx3d/step/body_position` для Play.

**Проектирование интеграции с Flutter Play**

– `Game3dPlayOverlay`: тик 60 Гц, `Lynx3dPhysicsController` (FFI) или Dart fallback;  
– `Lynx3dCoreViewport` (Windows): `lynx/viewport` MethodChannel, child HWND;  
– демо: `projects/platformer-demo-3d-room/` (room + PBR + physics + `core_forward_d3d12`).

**Сравнение с курсовой работой (стилистика проектирования)**

Как в курсовой использованы **слои и диаграммы**, в дипломе зафиксированы **слои View / FFI / Core / PAL** вместо Provider/Repository; алгоритмы описаны текстово (без подпунктов 2.2.1–2.2.3), листинги вынесены в **приложения**.

**Алгоритм шага физики (таблица 3 — этапы)**

| Шаг | Действие |
|-----|----------|
| 1 | Интеграция скорости dynamic-тел (гравитация) |
| 2 | Разрешение контактов с `static_planes` (room) |
| 3 | Попарное разрешение dynamic–dynamic (AABB) |
| 4 | Синхронизация позиций в Play через FFI |

*Таблица 3 — Алгоритм `Physics3dWorld::step`*

**Алгоритм Hi-Z occlusion (кратко)**

| Шаг | Действие |
|-----|----------|
| 1 | Очистка буфера дистанций (∞) |
| 2 | Растеризация AABB occluder в сетку 64×64 |

## ЗАКЛЮЧЕНИЕ

В ходе выполнения дипломной работы спроектирована и реализована кроссплатформенная игровая платформа **Lynx** с собственным ядром **Lynx Core** на языке Rust.

**Основные результаты:**

1. Проанализирована предметная область игровых движков, сформулированы функциональные и нефункциональные требования к платформе Lynx.  
2. Выполнен сравнительный анализ аналогов (Unity, Unreal, Godot, Bevy); обоснован выбор архитектуры Rust (ядро) + Flutter (редактор и Play).
