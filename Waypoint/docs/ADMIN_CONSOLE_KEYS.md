# Ключи и доступ к консоли Waypoint Metrics (admin / nexus)

После деплоя API с git вам нужны **учётная запись** и, для полноценной консоли, роль **admin** или **nexus** и **ключи активации** (60 символов). Этот файл — практическая схема без угадываний.

---

## 1. Что за ключи

| Тип | Длина | Зачем |
|-----|-------|--------|
| **Ключ активации admin** | ровно **60** символов | Привязать роль `admin` к уже залогиненному пользователю: `POST /auth/admin/activate` или экран **Настройки → подключить Метрику** в панели. |
| **Ключ активации nexus** | 60 символов | Роль `nexus` (платформа): `POST /auth/nexus/activate` или настройки realm **nexus**. |
| **Секрет API** | нет | `JWT_SECRET` в `.env` — не путать с ключами консоли; это подпись токенов на сервере. |

Одноразовые ключи **показываются только в момент создания** (ответ `POST /admin/keys`). В таблице БД хранится **хеш**; восстановить текст ключа из базы нельзя.

Автопул ключей в фоне дополняет таблицу **без сохранения plaintext** — такие строки **нельзя** скопировать пользователю. Для выдачи доступа используйте UI/API создания ключа под пользователем **nexus**.

---

## 2. Первый оператор nexus (после чистого деплоя)

Создать ключ в консоли может только пользователь с ролью **nexus**. Чтобы разорвать круг «нет nexus → нет ключей»:

### Вариант A — bootstrap при старте (по умолчанию в этом репозитории)

В `server/src/bootstrap.rs` задан **резервный email** владельца инстанса. Пока в БД нет ни одного `role = 'nexus'`, при каждом старте API пытается повысить пользователя с этим email (он уже должен существовать в таблице `users`).

**Цепочка «ваша почта → права nexus»:**

1. В корневом `.env` задайте **`NEXUS_BOOTSTRAP_ADMIN_EMAIL`** на **тот же адрес**, с которым будете регистрироваться (и включите доставку писем: **`OTP_WEBHOOK_URL`** + **`OTP_WEBHOOK_SECRET`**, см. `integrations/otp-webhook/send-otp.php` и `.env.example`). Для отладки без почты: **`OTP_LOG_CODES=1`** (код подтверждения в логах контейнера API).
2. Зарегистрируйтесь на сайте (**Регистрация**) с этим email, задайте пароль по правилам сложности, затем **подтвердите email** (8-значный код из письма, страница `/verify-email`).
3. **Войдите** в консоль (до подтверждения почты вход заблокирован).
4. **Перезапустите** API (`docker compose up -d --build` и т.д.), чтобы сработал bootstrap.
5. В логах — предупреждение об успешном повышении до `nexus` и выдаче realm **metric** + **nexus**. Обновите сессию (при необходимости выйдите и войдите) → **Admin keys** и остальные разделы nexus.

Если **не** задавать `NEXUS_BOOTSTRAP_ADMIN_EMAIL`, используется встроенная константа в `bootstrap.rs` (для форка замените её или задайте только env).

**Переопределить email без правки кода:** `NEXUS_BOOTSTRAP_ADMIN_EMAIL=you@example.com`.

**Отключить bootstrap** на чужом деплое: `NEXUS_BOOTSTRAP_SKIP=1`.

**Форкам:** замените константу в `bootstrap.rs` или полагайтесь только на переменные окружения.

Условие: в базе ещё **нет** ни одного пользователя с `role = 'nexus'`. Если nexus уже есть, в лог пишется `skip`.

### Вариант B — SQL в PostgreSQL

Подключитесь к БД и выполните (подставьте email):

```sql
UPDATE users
SET role = 'nexus', updated_at = NOW()
WHERE lower(trim(email)) = lower(trim('ops@ваш-домен.ru'));
```

Пользователь должен уже существовать (после регистрации). Затем войдите в консоль и выпускайте ключи через **Admin keys**.

## 3. Выдать admin другому человеку

1. Пользователь **регистрируется** и **входит** в консоль (роль `user` достаточно для входа).
2. Под **nexus** в **Admin keys** создаётся ключ с `key_kind: admin` (или через API `POST /admin/keys` с телом `{"key_kind":"admin"}` и полем `note`).
3. В ответе API один раз приходит поле **`key`** — передайте его получателю по безопасному каналу.
4. Получатель в **Настройках** вводит ключ (**подключить Метрику** / admin realm) или вызывает:
   ```http
   POST /auth/admin/activate
   Authorization: Bearer <текущий JWT>
   Content-Type: application/json

   {"key":"<60 символов>"}
   ```

Роль **nexus** выдаётся так же, но `POST /auth/nexus/activate` и ключ с `key_kind: nexus`.

## 4. Git и сервер

1. Пуш в репозиторий, на VPS `git pull`, `docker compose up -d --build` (или ваш скрипт).
2. Проверьте `GET /health`, `GET /ready`.
3. Настройте `CORS_ALLOWED_ORIGINS` под домен консоли и HTTPS при необходимости.
4. Выполните шаги из раздела 2, затем раздела 3.
