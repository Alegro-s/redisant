# Waypoint Metrics — веб-консоль и интеграция метрик

Документ описывает продуктовую роль **веб-консоли WaypointMetric** (каталог `web/`), способ входа, роли доступа и пути интеграции с API NEXUS. Игровой **2D-движок и редактор** — в клиенте Lynx и Lynx Cloud, не в этой консоли.

---

## 1. Назначение

Консоль предназначена для операторов и администраторов платформы:

- обзор состояния API и метрик;
- управление пользователями, ключами и чувствительными операциями (в рамках RBAC);
- работа с модулем **Waypoint** (ingest метрик и логов, задания, связанные сущности в API).

Это **не** игровой редактор NEXUS — только операционная консоль метрик и смежных модулей; границы платформы см. [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md).

---

## 2. Визуальный бренд

- **Цветовая тема:** тёмная/светлая в интерфейсе; акцент **изумрудный** (`primary` ≈ `#34B67A`, `success` ≈ `#10B981`). Настройка в `web/src/styles/supabase-theme.ts`.
- **Иконка и логотип-марк:** `web/public/favicon.svg` — знак «график / динамика» в зелёной палитре; используется как favicon, иконка PWA и марк в шапке (`LandingPage`, `Sidebar`).
- **PWA:** `public/manifest.webmanifest` — `theme_color` согласован с акцентом; при установке на домашний экран полоса статуса браузера подхватывает зелёный акцент.

## 3. Сборка и окружение фронтенда

| Шаг | Команда / действие |
|-----|-------------------|
| Зависимости | `cd admin-panel && npm install` |
| Разработка | `npm run dev` (Vite; в `vite.config.ts` по умолчанию порт **3000**) |
| Продакшен | `npm run build` → статика в `web/dist/` |

**Подключение к API:**

- **Разработка:** в `vite.config.ts` настроен прокси префикса `/api` → `http://127.0.0.1:8080`. Удобно задать в `.env` локально `VITE_API_URL=/api`, чтобы запросы шли через прокси и совпадали с прод-схемой.
- **Production-сборка:** в `vite.config.ts` для режима `production` подставляется **`VITE_API_URL` = `/api`**. Значит, за фронтом нужен reverse proxy, который отдаёт статику и проксирует `/api` на процесс API (см. [DEPLOY.md](../DEPLOY.md)).

Если собрать без такого прокси и без переопределения URL, клиент будет бить в несуществующий путь — вход и метрики «пропадут».

Фронтенд использует **axios с `withCredentials: true`**, чтобы браузер отправлял cookie сессии на тот же API-origin (с учётом CORS и списка разрешённых origin на сервере).

## 4. Аутентификация и сессия

1. **Логин / регистрация** вызывают соответствующие эндпоинты API (см. [openapi-waypoint-metric.yaml](openapi-waypoint-metric.yaml)).
2. Сервер выставляет **HttpOnly cookie** `nexus_session` (JWT внутри). TTL задаётся на стороне API (`SESSION_JWT_TTL_HOURS` и родственные настройки в `server/.env.example`).
3. После входа приложение опирается на cookie, а не на хранение токена в `localStorage` для сценария веб-консоли.
4. **Выход:** `POST /logout` очищает сессию на сервере и cookie в браузере (поведение описано в OpenAPI и реализации сервера).

**Продакшен:** при разрыве между **HTTP без TLS** и флагом **Secure** у cookie сессия в браузере не установится или не будет отправляться. Подробности — [OPERATIONS.md](OPERATIONS.md).

## 5. Роли и права (согласование UI и API)

В БД у пользователя есть роль: `user` | `admin` | `nexus`.

| Роль | Смысл |
|------|--------|
| `user` | Обычный пользователь консоли в рамках своих проектов и базовых экранов. |
| `admin` | Сотрудник/оператор: расширенные разделы (пользователи, инстансы, логи и т.д.) — см. ниже. |
| `nexus` | Команда платформы: всё, что у `admin`, плюс операции уровня **ключей активации** и **версий движка**. |

Матрица прав на фронтенде задана в `web/src/app/authz.ts` (тип `Permission`). Кратко:

- **Базовый набор:** дашборд, проекты, ассеты, workspace, метрики, запросы к БД (в UI), модульное тестирование.
- **Дополнительно для `admin`:** пользователи, инстансы, realtime, логи, задания, AI-анализ, журнал регистраций.
- **Только для `nexus`:** `admin-keys:manage`, `versions:manage`.

На сервере критичные маршруты дополнительно проверяются через `require_staff` / `require_nexus` (модуль `server/src/authz.rs`). Расхождение «я admin в голове, но API отвечает 403» чаще всего из-за **фактической роли в БД** или **устаревшей сессии** — см. [OPERATIONS.md](OPERATIONS.md).

## 6. Интеграция метрик и логов

### 6.1. Python (WaypointMetrics)

Каталог **`WaypointMetrics/`** — библиотека для отправки метрик и логов в API из Python-приложений. При работе через proxy или другой хост проверьте доступность API и ключи.

### 6.2. Открытый контракт API

Файл **[openapi-waypoint-metric.yaml](openapi-waypoint-metric.yaml)** описывает:

- регистрацию и вход (в т.ч. cookie);
- приём данных (ingest) с **`X-API-Key`**;
- чтение своих данных с **Bearer JWT** или сессией после входа в консоль.

Используйте его как эталон для генерации клиентов и для ручного тестирования в Swagger / Postman.

### 6.3. Ограничения и риски

- Нагрузка на ingest увеличивает запись в PostgreSQL — проверяйте лимиты и ретенцию.
- Эндпоинт **`/me/db/query`** (при включённых флагах) даёт **широкий read-only доступ** к данным от лица пользователя; это продуктовый и юридический риск — политика описана в [OPERATIONS.md](OPERATIONS.md).
